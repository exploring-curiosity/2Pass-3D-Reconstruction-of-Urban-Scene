\section{Method}
\label{sec:method}

Our system processes synchronized multi-camera video from an urban intersection through a two-pass pipeline: (1) static scene reconstruction to establish world geometry and camera parameters, and (2) dynamic object detection, tracking, and 3D localization.

    \centering

    \caption{\textbf{Multi-camera input configuration.} Eight synchronized cameras capture the intersection from four corners, providing comprehensive coverage with overlapping fields of view. Each corner station contains two cameras (left and right) oriented to maximize crosswalk visibility.}
    \label{fig:camera_setup}
\end{figure*}

%==============================================================================
\subsection{Pass 1: Static Scene Reconstruction}
\label{sec:pass1}
%==============================================================================

The first pass establishes a metrically consistent 3D representation of the static environment, including road surfaces, sidewalks, infrastructure, and parked vehicles. This geometric foundation is essential for accurate 2D-to-3D projection of dynamic objects in Pass 2.

\subsubsection{Temporal Median Background Extraction}

To isolate static scene elements from dynamic objects, we compute per-pixel temporal median images across the video sequence for each camera. Given a video sequence $\{I_t\}_{t=1}^{T}$ with $T$ frames, the background image $B$ is computed as:
\begin{equation}
    B(x, y) = \text{median}_{t \in [1, T]} \left( I_t(x, y) \right)
\end{equation}

This approach effectively removes transient objects (moving vehicles, pedestrians) while preserving static structures. We process 300 frames per camera at 10 FPS, providing 30 seconds of temporal coverage sufficient to eliminate most dynamic content.

\begin{figure}[h]
    \centering
    \includegraphics[width=0.95\linewidth]{assets/Static_background.png}
    \caption{\textbf{Temporal median background extraction.} Static background image computed from 300 frames, effectively removing all moving vehicles and pedestrians while preserving road markings, infrastructure, and parked vehicles.}
    \label{fig:static_background}
\end{figure}

\subsubsection{Multi-View Geometry Estimation with Pi3}

We employ Pi3~\cite{pi3}, a state-of-the-art multi-view 3D reconstruction method that jointly estimates camera intrinsics, extrinsics, and dense point clouds from uncalibrated images. Unlike traditional Structure-from-Motion (SfM) pipelines that require explicit feature matching and bundle adjustment, Pi3 uses a transformer-based architecture to directly regress 3D geometry from image pairs.

Given $N=8$ background images $\{B_i\}_{i=1}^{N}$, Pi3 processes all $\binom{N}{2} = 28$ image pairs and optimizes a global alignment that produces:
\begin{itemize}
    \item Camera intrinsic matrices $\{K_i\}_{i=1}^{N}$
    \item Camera extrinsic matrices $\{[R_i | t_i]\}_{i=1}^{N}$ in a shared world frame
    \item Dense point cloud $\mathcal{P} = \{(p_j, c_j)\}_{j=1}^{M}$ with 3D positions and RGB colors
\end{itemize}

The resulting point cloud contains approximately 1.2 million points with density exceeding 15,000 points/m$^2$ in the central intersection region.

\begin{figure}[h]
    \centering
    \includegraphics[width=0.95\linewidth]{assets/03_3d_point_cloud.png}
    \caption{\textbf{Dense 3D point cloud from Pi3.} Multi-view reconstruction produces a geometrically consistent point cloud of the intersection with accurate camera pose estimation for all 8 views.}
    \label{fig:point_cloud}
\end{figure}

\subsubsection{Ground Plane Estimation and Metric Calibration}

To enable accurate projection of 2D detections to 3D world coordinates, we estimate the ground plane from the reconstructed point cloud using RANSAC-based plane fitting. We first apply semantic segmentation using SegFormer~\cite{segformer} trained on Cityscapes~\cite{cityscapes} to identify road and sidewalk regions in each camera view. Points projecting to these semantic regions are used as inliers for robust plane estimation:
\begin{equation}
    \pi: ax + by + cz + d = 0, \quad \text{s.t.} \quad a^2 + b^2 + c^2 = 1
\end{equation}

Since Pi3 outputs geometry in arbitrary scale, we recover metric scale using known physical dimensions. We measure the width of standard crosswalk stripes (typically 0.3m) and vehicle dimensions visible in the scene to compute a scale factor $S$ that transforms the point cloud to real-world meters.

    \caption{\textbf{Semantic segmentation for ground plane estimation.} SegFormer predictions identify road (purple), sidewalk (pink), and curb regions across all camera views, providing robust inliers for RANSAC plane fitting.}

\end{figure}

\subsection{Pass 2: Dynamic Object Detection and Tracking}
\label{sec:pass2}
%==============================================================================

The second pass processes the full video sequences to detect, track, and localize dynamic objects (vehicles and pedestrians) in 3D world coordinates using the camera parameters and ground plane from Pass 1.

\subsubsection{Object Detection with YOLOv8}

We employ YOLOv8x~\cite{yolov8}, the largest variant of the YOLO family, for real-time object detection. The model is applied to each camera stream independently, detecting objects in the following categories: \texttt{person}, \texttt{bicycle}, \texttt{car}, \texttt{motorcycle}, \texttt{bus}, \texttt{truck}.

For each detection, we extract:
\begin{itemize}
    \item Bounding box coordinates $(x_1, y_1, x_2, y_2)$
    \item Class label $c \in \mathcal{C}$
    \item Confidence score $s \in [0, 1]$
\end{itemize}

We apply a confidence threshold of $\tau = 0.25$ to balance recall and precision, as lower-confidence detections are valuable for tracking through occlusions.

\begin{figure*}[t]
    \centering
    \includegraphics[width=\textwidth]{assets/06_yolov8_detection.png}
    \caption{\textbf{YOLOv8x detection results.} High-confidence detections of vehicles and pedestrians across multiple camera views. The detector achieves $>$95\% recall on visible objects with real-time inference at 30+ FPS.}
    \label{fig:yolo_detection}
\end{figure*}

\subsubsection{Multi-Object Tracking with ByteTrack}

To maintain consistent object identities across frames, we employ ByteTrack~\cite{bytetrack}, a state-of-the-art multi-object tracking algorithm. ByteTrack's key innovation is associating \emph{every} detection box, including low-confidence ones, which significantly improves tracking through occlusions.

The tracking pipeline operates as follows:
\begin{enumerate}
    \item \textbf{High-confidence matching:} Associate detections with $s > \tau_{\text{high}} = 0.6$ to existing tracks using IoU-based Hungarian matching
    \item \textbf{Low-confidence recovery:} Match remaining detections with $s > \tau_{\text{low}} = 0.1$ to unmatched tracks, recovering occluded objects
    \item \textbf{Track management:} Initialize new tracks for unmatched high-confidence detections; terminate tracks after $T_{\text{lost}} = 30$ frames without association
\end{enumerate}

This produces per-camera track sequences $\mathcal{T}_i = \{(t, \text{id}, \text{bbox}, \text{class})\}$ for each camera $i$.

\subsubsection{2D to 3D Projection}

Given a 2D bounding box detection, we project the bottom-center point (ground contact) to 3D world coordinates using the camera parameters from Pass 1 and the estimated ground plane.

For a 2D point $(u, v)$ in camera $i$, the corresponding 3D ray is:
\begin{equation}
    \mathbf{r}(t) = \mathbf{o}_i + t \cdot K_i^{-1} \begin{bmatrix} u \\ v \\ 1 \end{bmatrix}
\end{equation}
where $\mathbf{o}_i$ is the camera center. The 3D ground contact point is the intersection of this ray with the ground plane $\pi$:
\begin{equation}
    \mathbf{p}_{\text{3D}} = \mathbf{r}(t^*), \quad t^* = -\frac{\mathbf{n} \cdot \mathbf{o}_i + d}{\mathbf{n} \cdot (K_i^{-1} [u, v, 1]^T)}
\end{equation}
where $\mathbf{n} = [a, b, c]^T$ is the ground plane normal.

\subsubsection{Multi-Camera Track Association}

To merge tracks of the same physical object observed across multiple cameras, we perform multi-camera association using spatial-temporal clustering. Two tracks $\mathcal{T}_i^a$ and $\mathcal{T}_j^b$ from cameras $i$ and $j$ are merged if they satisfy:

\begin{enumerate}
    \item \textbf{Category consistency:} Same object class (vehicle or pedestrian)
    \item \textbf{Spatial proximity:} 3D distance $< \delta_{\text{spatial}}$ (2.0m for vehicles, 1.0m for pedestrians)
    \item \textbf{Temporal overlap:} Overlapping time interval $\geq 0.3$s and $\geq 30\%$ relative overlap
\end{enumerate}

We use union-find clustering to transitively merge all associated tracks, producing global object identities $\mathcal{G} = \{g_k\}$ where each $g_k$ contains all track observations of a single physical object.

\subsubsection{Canonical 3D Primitive Representation}

Each global object is represented as a canonical 3D primitive in the world coordinate frame, enabling efficient ray-geometry intersection for visibility analysis.

\textbf{Vehicles} are represented as oriented bounding boxes (OBB) aligned with the object's motion direction. Unlike axis-aligned bounding boxes (AABB) that overestimate volume during turns, OBBs accurately capture the vehicle's footprint:
\begin{equation}
    \text{OBB}_k = (\mathbf{c}_k, \mathbf{R}_k, \mathbf{d}_k)
\end{equation}
where $\mathbf{c}_k$ is the center position, $\mathbf{R}_k$ is the rotation matrix aligned with velocity, and $\mathbf{d}_k$ are class-specific dimensions (car: $4.5 \times 1.8 \times 1.5$m, truck: $7.0 \times 2.5 \times 3.0$m, bus: $12.0 \times 2.5 \times 3.2$m).

\textbf{Pedestrians} are represented as vertical cylinders:
\begin{equation}
    \text{Cyl}_k = (\mathbf{c}_k, r=0.25\text{m}, h=1.7\text{m})
\end{equation}

\subsubsection{Motion Classification}

Each tracked object is classified as \textit{stationary} or \textit{moving} based on its 3D trajectory statistics:
\begin{equation}
    \text{class} = \begin{cases}
        \text{stationary} & \text{if } \sigma(\mathbf{p}) < \epsilon_\sigma \text{ and } \Delta_{\max} < \epsilon_\Delta \\
        \text{moving} & \text{otherwise}
    \end{cases}
\end{equation}
where $\sigma(\mathbf{p})$ is the standard deviation of 3D positions, $\Delta_{\max}$ is the maximum displacement, and $\epsilon_\sigma = 0.5$m, $\epsilon_\Delta = 1.0$m are empirically determined thresholds.

This classification enables separate handling of parked vehicles (potential static occluders) and moving traffic (dynamic visibility hazards).

\subsection{Implementation Details}
\label{sec:implementation}
%==============================================================================

\textbf{Hardware:} All experiments are conducted on a workstation with an NVIDIA RTX 4090 GPU (24GB VRAM), Intel i9-13900K CPU, and 64GB RAM.

\textbf{Software:} We implement our pipeline in Python using PyTorch~\cite{pytorch}. Pi3 reconstruction uses the official implementation with default hyperparameters. YOLOv8x detection runs at 30+ FPS per camera. ByteTrack operates in real-time with negligible overhead. Depth Anything V2 uses the ViT-Large backbone for optimal accuracy.

\textbf{Data:} We process 8 synchronized video streams at 1920$\times$1080 resolution and 30 FPS. Each video contains approximately 9,000 frames (5 minutes of footage) capturing typical intersection traffic patterns.
