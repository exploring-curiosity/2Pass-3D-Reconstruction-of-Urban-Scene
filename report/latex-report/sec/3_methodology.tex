\section{\black{Method}}
\label{sec:method}

\black{Our system processes multi-camera synchronized video from a 4-corner intersection to reconstruct static and dynamic 3D scene elements for Line-of-Sight visibility analysis.}

\subsection{\blue{Pass 1: Static Scene Reconstruction}}
\blue{We extract static background images per camera via temporal median filtering ($B(x,y) = \text{median}_t(I_t(x,y))$ over 300 frames) and apply Pi3~\cite{pi3} for multi-view geometry estimation. Pi3 jointly optimizes camera poses and produces a dense global point cloud ($\sim$1.2M points) in a shared world frame with camera intrinsics $K_i$ and extrinsics (camera-to-world poses $T_{c2w}$). For ground plane estimation, we apply SegFormer~\cite{segformer} semantic segmentation to identify road/sidewalk regions, then use RANSAC plane fitting. Metric scale is recovered using known crosswalk stripe widths (0.3m).}

\subsection{\black{Pass 2: Dynamic Object Tracking}}

\subsubsection{\black{Detection and Per-Camera Tracking}}
\black{We apply YOLOv8x~\cite{yolov8} for object detection (person, car, truck, bus, bicycle) and ByteTrack~\cite{bytetrack} for per-camera multi-object tracking. ByteTrack associates both high and low-confidence detections, improving tracking through occlusions.}

\subsubsection{\blue{Stereo Triangulation for 3D Localization}}
\blue{Each corner has a stereo pair (left/right cameras). For matched detections across the pair, we triangulate 3D positions using:}
\begin{equation}
\blue{\mathbf{X} = \text{triangulate}(P_L, P_R, \mathbf{u}_L, \mathbf{u}_R)}
\end{equation}
\blue{where $P = K[R|t]$ are projection matrices from Pi3 camera parameters. For single-camera detections, we project to the ground plane ($z=0$) by ray-plane intersection.}

\subsubsection{\blue{Kalman Filter Tracking}}
\blue{Each 3D track maintains a Kalman filter with 6-state (position + velocity). The filter predicts positions between frames and updates with triangulated measurements, providing smooth trajectories and handling temporary occlusions.}

\begin{figure}[h!]
    \centering
    \includegraphics[width=0.8\linewidth]{assets/object_tracking.png}
    \caption{\blue{YOLOv8x detection with ByteTrack maintaining consistent IDs}}
    \label{fig:object_tracking}
\end{figure}

\subsubsection{\blue{Multi-Camera Association}}
\blue{Tracks from different stereo pairs are merged using spatial-temporal clustering: (1) same object category, (2) 3D proximity $<$2.0m for vehicles, $<$1.0m for pedestrians, (3) temporal overlap $\geq$30\%. Union-find clustering produces global object IDs.}

\subsubsection{\blue{Canonical Primitive Representation}}
\blue{Each object is represented as a 3D primitive: oriented bounding boxes for vehicles with class-specific dimensions (car: 4.5$\times$1.8$\times$1.5m, truck: 7.0$\times$2.5$\times$3.0m), and vertical cylinders for pedestrians (r=0.25m, h=1.7m). Objects are classified as static or moving based on trajectory variance ($\sigma < 0.5$m).}

\subsection{\black{Gaussian Splatting}}
\subsubsection{\blue{Gaussian Splatting for Static Scene Geometry}}
\blue{
The dense static point cloud produced in Pass 1 (via Pi3) is converted into a Gaussian Splatting representation using a 3D Gaussian Splatting (3DGS) formulation. Each point is modeled as an anisotropic 3D Gaussian parameterized by position, covariance, opacity, and color, converting the discrete point cloud into a continuous density field while preserving fine structural detail. The resulting static Gaussian scene serves as the primary environmental occlusion layer for visibility analysis.
}

We train the 3DGS model for 30,000 steps, which takes approximately 6 hours using Apple's MPS backend using the \textit{Brush} library. The resulting reconstruction is shown in Fig~\ref{fig:camera_fov_gaussian}. While the overall structure is captured, the splats exhibit significant self-occlusion artifacts. We attribute this primarily to the limited number of fixed camera views. In particular, planar regions such as road surfaces appear to be reconstructed from misaligned observations across cameras, resulting in overlapping or duplicated splats that cannot be reliably merged or pruned.

\subsubsection{\blue{Integration with Line-of-Sight Analysis}}
\blue{
During Pass 3, Line-of-Sight ray casting is performed against a unified Gaussian scene composed of static Gaussian splats for infrastructure and dynamic Gaussian splats for pedestrians and vehicles. Rays cast from pedestrian eye points accumulate opacity as they traverse Gaussian densities, and are considered occluded once transmittance falls below a fixed threshold. Visibility scores are computed using the same multi-ray bundle strategy described earlier, but with Gaussian-based density integration instead of point-wise intersections. This improves robustness in cluttered scenes by reducing sensitivity to point cloud sparsity and enabling smoother visibility transitions.
}

\subsubsection{\black{Role of Gaussian Splatting in the Overall Pipeline}}
\black{
Gaussian splatting acts as a geometric representation layer rather than a replacement for reconstruction or tracking. Pi3 provides the global frame and static structure; YOLOv8x and ByteTrack provide dynamic object identities; canonical primitives provide semantic abstraction; and Gaussian splatting provides a dense spatial medium for reliable ray-based LoS auditing. Attempts to clean the point cloud using Blender were not feasible due to scale, with over one million points, and mesh-based substitutes suffered from the same misalignment issues. We believe these limitations can be mitigated by incorporating additional camera viewpoints to improve geometric consistency.
}

\subsection{\black{Pass 3: Line-of-Sight Audit}}
\black{For visibility analysis, we implement a ray-casting pipeline that determines precisely when an approaching vehicle becomes visible to a pedestrian. The pipeline processes a colored point cloud where dynamic objects (pedestrians, vehicles) are distinguished from static infrastructure via RGB color coding. To handle the complexity of dense point clouds and arbitrary metric scales, we employ scene segmentation, spatial voxelization, and biological scale calibration.}


\subsubsection{\blue{Scene Segmentation and Scale Calibration}}
\blue{The input point cloud contains color-coded objects: pedestrians (blue), cars (red), trucks (green), and cycles (pink). We segment the scene by computing Euclidean distance in RGB space to reference colors, classifying points within a tolerance threshold ($\delta < 0.15$). Points not matching any dynamic object color are classified as static infrastructure. Dynamic points are then clustered using DBSCAN (eps=1.0m for vehicles, 0.5m for pedestrians) to extract individual object instances.}

\blue{Since Pi3 outputs geometry in arbitrary units, we recover metric scale using a biological prior. We compute the median height of pedestrian clusters (z-range) and calculate a scale factor $S = 1.7\text{m} / \text{median\_height}$ to anchor the median to 1.7m (average human height). This aligns the entire scene to real-world dimensions without relying on potentially degraded road markings.}

\subsubsection{\blue{Spatial Indexing for Ray Casting}}
\blue{To make ray-casting computationally feasible against a dense point cloud, we build two complementary occupancy structures: (1) a \textbf{Voxel Occupancy Grid} for static infrastructure with 20cm leaf size, creating a lightweight occupancy map that preserves major occluders (poles, parked trucks) while accelerating intersection testing; (2) \textbf{KD-tree structures} for each dynamic object cluster, enabling efficient proximity queries for ray-object intersections.}

\subsubsection{\black{Visibility Scoring}}
\black{We define visibility not as a binary state, but as a confidence score. For each pedestrian-vehicle pair:}
\begin{enumerate}
    \item \black{\textbf{Ray Bundle Casting:}} \black{We cast rays from the pedestrian's eye point (1.6m above ground) to $K=5$ keypoints on the vehicle: bumper center, left headlight, right headlight, hood center, and roof front. Each ray is marched with 10cm step size, checking intersections against both static voxels and dynamic object KD-trees.}
    \item \black{\textbf{Visibility Score ($V_t$):}} \black{A vehicle is classified as \textit{Visible} only if $>60\%$ of rays reach the target without intersecting occupied voxels or other dynamic primitives (excluding the pedestrian and target vehicle themselves).}
    \item \black{\textbf{Occluder Identification:}} \black{For each blocked ray, we identify whether the occlusion is caused by static infrastructure (poles, signs), parked vehicles (stationary objects), moving vehicles, or other pedestrians, enabling targeted safety recommendations. The primary occluder is determined by majority vote across blocked rays.}
\end{enumerate}
