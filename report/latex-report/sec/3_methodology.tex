\section{\blue{Method}}
\label{sec:method}

\blue{Our system processes multi-camera synchronized video from a 4-corner intersection to reconstruct static and dynamic 3D scene elements for Line-of-Sight visibility analysis.}

\subsection{\blue{Pass 1: Static Scene Reconstruction}}
\blue{We extract static background images per camera via temporal median filtering ($B(x,y) = \text{median}_t(I_t(x,y))$ over 300 frames) and apply Pi3~\cite{pi3} for multi-view geometry estimation. Pi3 jointly optimizes camera poses and produces a dense global point cloud ($\sim$1.2M points) in a shared world frame with camera intrinsics $K_i$ and extrinsics (camera-to-world poses $T_{c2w}$). For ground plane estimation, we apply SegFormer~\cite{segformer} semantic segmentation to identify road/sidewalk regions, then use RANSAC plane fitting. Metric scale is recovered using known crosswalk stripe widths (0.3m).}

\subsection{\blue{Pass 2: Dynamic Object Tracking}}

\subsubsection{\blue{Detection and Per-Camera Tracking}}
\blue{We apply YOLOv8x~\cite{yolov8} for object detection (person, car, truck, bus, bicycle) and ByteTrack~\cite{bytetrack} for per-camera multi-object tracking. ByteTrack associates both high and low-confidence detections, improving tracking through occlusions.}

\subsubsection{\blue{Stereo Triangulation for 3D Localization}}
\blue{Each corner has a stereo pair (left/right cameras). For matched detections across the pair, we triangulate 3D positions using:}
\begin{equation}
\blue{\mathbf{X} = \text{triangulate}(P_L, P_R, \mathbf{u}_L, \mathbf{u}_R)}
\end{equation}
\blue{where $P = K[R|t]$ are projection matrices from Pi3 camera parameters. For single-camera detections, we project to the ground plane ($z=0$) by ray-plane intersection.}

\subsubsection{\blue{Kalman Filter Tracking}}
\blue{Each 3D track maintains a Kalman filter with 6-state (position + velocity). The filter predicts positions between frames and updates with triangulated measurements, providing smooth trajectories and handling temporary occlusions.}

\begin{figure}[h!]
    \centering

    \caption{\blue{YOLOv8x detection with ByteTrack maintaining consistent IDs}}

\subsubsection{\blue{Multi-Camera Association}}
\blue{Tracks from different stereo pairs are merged using spatial-temporal clustering: (1) same object category, (2) 3D proximity $<$2.0m for vehicles, $<$1.0m for pedestrians, (3) temporal overlap $\geq$30\%. Union-find clustering produces global object IDs.}

\subsubsection{\blue{Canonical Primitive Representation}}
\blue{Each object is represented as a 3D primitive: oriented bounding boxes for vehicles with class-specific dimensions (car: 4.5$\times$1.8$\times$1.5m, truck: 7.0$\times$2.5$\times$3.0m), and vertical cylinders for pedestrians (r=0.25m, h=1.7m). Objects are classified as static or moving based on trajectory variance ($\sigma < 0.5$m).}

\subsection{\green{Pass 3: Line-of-Sight Audit}}
\green{For visibility analysis, we implement a ray-casting pipeline that determines precisely when an approaching vehicle becomes visible to a pedestrian. The pipeline processes a colored point cloud where dynamic objects (pedestrians, vehicles) are distinguished from static infrastructure via RGB color coding. To handle the complexity of dense point clouds and arbitrary metric scales, we employ scene segmentation, spatial voxelization, and biological scale calibration.}

\begin{figure}[t]
    \centering
    \includegraphics[width=0.85\linewidth]{assets/bev_combined.png}
    \caption{\green{Bird's-eye view visualization of line-of-sight analysis showing visibility rays from pedestrians to vehicles. Green rays indicate clear LOS ($\geq$60\% visibility), orange indicates partial visibility (40-60\%), and red indicates occluded paths ($<$40\%).}}
    \label{fig:los_bev}
\end{figure}

\subsubsection{\green{Scene Segmentation and Scale Calibration}}
\green{The input point cloud contains color-coded objects: pedestrians (blue), cars (red), trucks (green), and cycles (pink). We segment the scene by computing Euclidean distance in RGB space to reference colors, classifying points within a tolerance threshold ($\delta < 0.15$). Points not matching any dynamic object color are classified as static infrastructure. Dynamic points are then clustered using DBSCAN (eps=1.0m for vehicles, 0.5m for pedestrians) to extract individual object instances.}

\green{Since Pi3 outputs geometry in arbitrary units, we recover metric scale using a biological prior. We compute the median height of pedestrian clusters (z-range) and calculate a scale factor $S = 1.7\text{m} / \text{median\_height}$ to anchor the median to 1.7m (average human height). This aligns the entire scene to real-world dimensions without relying on potentially degraded road markings.}

\subsubsection{\green{Spatial Indexing for Ray Casting}}
\green{To make ray-casting computationally feasible against a dense point cloud, we build two complementary occupancy structures: (1) a \textbf{Voxel Occupancy Grid} for static infrastructure with 20cm leaf size, creating a lightweight occupancy map that preserves major occluders (poles, parked trucks) while accelerating intersection testing; (2) \textbf{KD-tree structures} for each dynamic object cluster, enabling efficient proximity queries for ray-object intersections.}

\subsubsection{\green{Visibility Scoring}}
\green{We define visibility not as a binary state, but as a confidence score. For each pedestrian-vehicle pair:}
\begin{enumerate}
    \item \green{\textbf{Ray Bundle Casting:}} \green{We cast rays from the pedestrian's eye point (1.6m above ground) to $K=5$ keypoints on the vehicle: bumper center, left headlight, right headlight, hood center, and roof front. Each ray is marched with 10cm step size, checking intersections against both static voxels and dynamic object KD-trees.}
    \item \green{\textbf{Visibility Score ($V_t$):}} \green{A vehicle is classified as \textit{Visible} only if $>60\%$ of rays reach the target without intersecting occupied voxels or other dynamic primitives (excluding the pedestrian and target vehicle themselves).}
    \item \green{\textbf{Occluder Identification:}} \green{For each blocked ray, we identify whether the occlusion is caused by static infrastructure (poles, signs), parked vehicles (stationary objects), moving vehicles, or other pedestrians, enabling targeted safety recommendations. The primary occluder is determined by majority vote across blocked rays.}
\end{enumerate}
